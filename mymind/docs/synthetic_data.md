# 合成数据、实验结果与已知问题

更新：2026-11-07。本文汇总已完成实验的数据口径与内容复核结论。原始题集、私有评分标准、教师轨迹和运行记录单独保留；本文中的实例为内容摘要，不替代完整原始证据。代码入口见[训练与评测](../rl/README.md)及[数据构建](../benchmarks/README.md)。

## 任务与数据形态

MyMind 的策略实验使用合成客服任务，给定 billing 或 technical 角色。模型输入包含 task_id、role、user_text 和带 reference_id 的 records；模型自行调用 search、读取实际政策正文，然后输出结构化的 answer、request_info 或 escalate。facts、reasons、next_steps、missing_info 需要匹配业务对象、字段、状态和引用依据。

评分标准在模型可见输入之外，约束允许处置、必要事实、证据支持和条件动作。“私有”表示对被评测策略隔离。训练奖励及生成后的评价可以使用标准；标准答案不进入学生提示。教师推理、system、用户、工具观察及 padding 不参与 SFT 直接监督，assistant 动作与终止回复参与监督。

完整成功要求内容、协议和证据同时合格。严重错误与协议错误可以重叠；评分提前返回后的未检查项保持未知。完整成功为零不意味着所有业务判断均错误，需要结合逐项内容理解。

## 历史正式数据与结果

原始 600 题由固定合成政策、实例条件及标准构建，按场景组分为 train/validation/test = 400/80/120，分别覆盖 20/7/8 组。它们不是独立真实客服抽样，也不能称为人工金标。

训练侧采用 158 条成功教师示范，训练 SFT120；RL 运行 80 步，按验证集选择 RL40。原 120 题结果如下：

| 指标 | Base | SFT120 | RL40 |
| --- | ---: | ---: | ---: |
| 完整成功 | 0 | 43 | 43 |
| 严重错误 | 38 | 38 | 27 |
| 协议错误 | 76 | 24 | 19 |

RL 新增 3 题成功，同时失去 3 题，完整成功数量没有增加。历史正式评分为 v13，不能把当前评分器重判结果当作当时模型收益。

留存数据审计揭示以下偏差和覆盖限制：

- 成功筛选后，request_info 类从原训练集 23.75% 降至示范集 13.29%；多对象任务从 25.00% 降至 18.35%。这证明分布变化，不能据此直接断定低入选率的原因。
- 158 条示范共调用 search 310 次，但观察结果后再次搜索为 0/158；同一次 assistant 消息中的多个查询不算反馈补检。
- 所选 RL40 实际覆盖 20 个不同训练任务、20 组和 80 条轨迹；完整 RL80 覆盖 40 个任务、40 组和 160 条轨迹，未遍历全部 158 题。
- 历史汇总记载 717 个教师候选，目前可读取 158 份入选原件；其余 559 份未取得，不能重建完整拒绝原因分布，也不能把缺失原件当作失败候选。

## 当前三分支先导

当前标准为 success-pool-evidence-v5，评分为 v17-policy-constant-equivalence。来源包含未用于开发反馈的旧 train 实例和独立新合成事件。先采集并验收教师成功原件，再按 family_id 整族划分；同事件、改写及反事实不跨集合，开发族与旧封存测试不回流。

六分支统一成功池为 28 题、16 族。F02 严重故障仅 1 题、M02 多笔退款 2 题、P04 权限未知 2 题，可用成功族不足以支撑原六分支三集合，因此先导收窄为以下 23 题：

| 分支 | 含义 | train | validation | test | 合计 |
| --- | --- | ---: | ---: | ---: | ---: |
| A01 | 明确过期 | 3 | 2 | 2 | 7 |
| B01 | 疑似双扣 | 3 | 2 | 2 | 7 |
| R01 | 审核未知 | 5 | 2 | 2 | 9 |
| 合计 | 16 个来源族 | 11（8族） | 6（4族） | 6（4族） | 23 |

每题只保留最早合格教师原件，参考回答和编辑样例不计教师成功。validation/test 的教师轨迹不用于训练或学生评价输入。筛选后的数据代表教师能成功完成的子集，不代表全部候选分布。

本轮从原始 Qwen3-4B-Instruct-2507 重新初始化 LoRA，不使用旧 SFT120/RL40。SFT 的 11 条训练数据共 3,309 个监督 token 位置，3 epoch、33 次样本呈现、9 次更新；验证候选 3/6/9 步成功 0/0/1，选择 SFT9。

RL 从本轮 SFT 起点新建优化器，11 组、每组 4 条轨迹，共 44 条、22 次更新；使用组内奖励减均值、DAPO 有效模型 token 分母、β=0。奖励为 40 条 0 和 4 条 -1，仅 3 组有奖励差异。验证候选 8/16/22 步成功均 0，按严重错误、协议错误及更早步数选择 RL8。RL8 只经历前 4 组，其中 2 组有奖励差异。

| 最终 test，各 6 题 | Base | SFT9 | RL8 |
| --- | ---: | ---: | ---: |
| 完整成功 | 0 | 0 | 0 |
| 严重错误 | 1 | 1 | 1 |
| 协议错误 | 2 | 2 | 3 |

本轮没有观察到最终测试收益，与历史 120 题不合并分母或直接计算提升。已有梯度与参数更新记录；评价时 SFT/RL adapter 各 504/504 张量匹配。RL 训练起点逐张量匹配记录缺失，配置和源码指向 SFT9。

## 已观察到的失败实例

以下摘要来自最终 test 的逐题内容复核，未修改原始输出或评分。

| 任务 ID | 输入与要求 | 学生输出的问题 |
| --- | --- | --- |
| mainline-balanced-A01-13 | Q1 本次认证明确过期，应结合实际认证事实和政策重新授权 | 三模型认证判断和重新授权方向正确，但理由及动作只引政策，缺少本题 user:3 事实前提 |
| expansion-A01-technical-event-period-close | Q1 的响应包含 401 和明确过期信息 | 三模型均漏 http_status=401；引用有的只含事实，有的只含政策 |
| mainline-balanced-B01-16 | O1 疑似双扣，需当前人工核验，并收集交接材料 | 三模型均误写 R1，采用 request_info，额外字段 payment_category 不在协议目录 |
| expansion-B01-billing-event-credit-note | 对订单对象处理疑似双扣 | 三模型均误用 R1 和 evidence_insufficient；RL 额外生成非法字段，新增协议失败 |
| expansion-R01-billing-event-credit-note | 审核状态未知，应先确认 approval_status，审核通过后再按条件询问时效 | 输出等待到账或无条件索取 elapsed_workdays，遗漏审核状态及 if_approved 条件 |

A01 有已取得正确政策仍失败的实例，不能把所有失败统一归因于检索。对象混淆、错误处置和未知状态混用也不能只解释为引用格式问题。唯一 SFT validation 成功说明并非所有生成都失败，但不足以证明已掌握训练任务。

## 当前证据能回答什么

当前尚无 Base 与 SFT9 在全部 11 条 train 上的自由生成对照，无法区分欠拟合、训练与推理接口差异及泛化失败。RL 缺少完整成功或 0.3 奖励轨迹，主要只能区分严重失败和其他失败；参数更新次数不能替代有效奖励信号。

数据规模小、单 seed、教师成功筛选及事后收窄分支共同限制结论。最新 test 已用于失败分析，后续仅作为回归材料；换顺序、话术或 ID 不产生新的独立测试数据。标准修订后的离线通过不计模型收益。

## 公开资源与原件边界

仓库提供生成与评分代码、少量开发样例、配置模板、测试和上述结果摘要。完整合成题集、来源清单、教师候选、私有标准、原始学生输出、监督 token 导出及运行记录不随 Git 发布；模型权重和索引也不包含在仓库中。

需要判断数据内容时，应配对读取同题的模型可见输入、实际检索正文、教师合格原件、Base/SFT/RL 原始输出和评分依据。仅有本页无法独立重算结果。来源与划分问题还需要任务到 family_id、split 的映射；训练问题还需要实际模板、labels 和配置。历史源码快照与当前源码分别使用，不能混为一次运行的证据。
