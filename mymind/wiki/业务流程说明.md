# mymind 业务流程说明

适用范围：本地 Python / FastAPI 主版本，2026-10-07。

本文按 `api/main.py`、`agents/agent_orchestrator.py` 和各业务模块的实际执行顺序说明请求。模型生成的意图与工具选择存在不确定性；图中的条件节点表示程序真正检查的分支。

## 1. `/chat` 主流程

![请求主流程](assets/flows/01-chat-flow.png)

`POST /chat` 接收 `message`、`user_id`（默认 `anonymous`）和可选 `conv_id`。未传会话 ID 时生成 UUID；服务未初始化时返回 HTTP 503。

1. `MemoryManager.get_context()` 读取 Redis 工作记忆与会话摘要，按用户和当前问题检索 Chroma 情景记忆，再读取用户画像。
2. 最近 5 条工作记忆组成意图识别的 `history`。Orchestrator 持有的识别器输出意图、领域、置信度、紧急度、实体和来源分数。
3. `ContextBuilder` 在默认 8000 字符背景预算内组合记忆。`/chat` 传入的知识文本为空；当前问题另放在 `Request.message`，不会作为旧记忆被预算裁剪。
4. `Request` 携带背景、历史、实体、意图与完整 UUID `request_id`，进入 `AgentOrchestrator.run()`。
5. Orchestrator 先判断低置信度澄清，再决定升级或主辅路由。单 Agent 执行 `_execute()`；主辅 Agent 用 `asyncio.gather()` 并行处理同一个请求。
6. Agent 在工具循环中自行选择是否调用 `search_knowledge_base`。检索结果以 Provider 对应的工具结果消息回送模型，供后续回答使用。
7. `/chat` 从实际工具轨迹汇总知识状态，然后依次写用户消息和最终助手回复。达到 15 条消息的那次写入会同步触发压缩。
8. 用户画像更新作为受生命周期管理的后台任务启动。HTTP 响应不等待画像提炼；服务关闭时会处理未结束任务。

`/chat` 没有按意图预检索的步骤。`POST /search` 是用户显式发起的独立检索接口，使用同一工具管理器。

## 2. 意图识别

![意图融合流程](assets/flows/02-intent-fusion.png)

### 三路识别与领域合分

LLM 和可用的 Embedding 分支并行，Pattern 同步完成。意图 Embedding 是轻量模板匹配：客户端不提供向量资源时使用本地字符 n-gram 向量；它与知识库的 Chroma Embedding 分开。配置兼容 Base URL 时，识别器禁用该 Embedding 分支。

| 情况 | LLM 权重 | Embedding 权重 | Pattern 权重 |
| --- | ---: | ---: | ---: |
| Embedding 开启 | 0.70 | 0.20 | 0.10 |
| Embedding 关闭 | 0.85 | 0 | 0.15 |

每路给出一个意图及原始置信度。`_vote()` 同时累计具体意图分和 `intent_group` 分：先选总分最高的领域，再选该领域内分数最高的具体意图。

| 具体意图 | 领域 |
| --- | --- |
| `order_status`、`logistics` | `query` |
| `refund`、`invoice`、`payment_issue` | `billing` |
| `account_security` | `account` |
| `technical_login`、`technical_crash` | `technical` |
| `human_handoff` | `escalation` |

其余意图归入同名领域。例如 LLM 给 `billing/0.3`，Embedding 给 `technical_login/0.9`，Pattern 给 `technical/0.4`，加权后为账单组 `0.21`、技术组 `0.18+0.04=0.22`。技术组获胜，组内选择 `technical_login`。阈值为 `0.2` 时返回该意图和 `0.22`；默认阈值为 `0.5` 时返回 `other`，置信度仍为 `0.22`。

### Pattern 细化和失败兜底

Pattern 仅在以下条件同时成立时细化胜出的粗意图：

- 当前组内胜出的是可细化的粗意图。
- Pattern 是具体意图，且属于胜出的同一领域。
- Pattern 置信度至少为 `0.5`，胜出领域分低于 `0.8`。

细化后置信度取领域分与 Pattern 置信度中的较大值，并写入 `source_scores.refined_by_pattern`。LLM 的账单结果不会被技术 Pattern 改成登录故障。

LLM 失败走独立兜底：先使用具有正置信度的 Embedding 结果，其次使用 Pattern，否则返回 `other/0`。这个分支不再进行加权投票。`source_scores` 的三个来源分始终是原始置信度。

### 紧急度与澄清

实体包括订单号、日期、金额和错误码；`product` 当前为空列表。紧急关键词决定 LOW/MEDIUM/HIGH/CRITICAL，例如 `紧急`、`urgent`、`立刻` 可触发 CRITICAL。

当意图为 `other`、消息去空白后长度大于 2、置信度低于 `0.5` 时，`run()` 直接返回澄清话术，跳过 Agent 模型调用。该检查在路由前执行，因此这一类低置信度请求不会继续进入升级或专业路由。HIGH 本身不强制升级。

## 3. 主辅 Agent 路由

![Agent 路由流程](assets/flows/03-agent-routing.png)

### 升级分支

通过澄清检查后，CRITICAL 或 `escalation/human_handoff` 触发升级路由。默认 `AGENT_ESCALATION_ENABLED=false`，没有独立升级池，交给 GeneralAgent 接待并标记 `escalated=true`。开启独立升级节点后由 EscalationAgent 整理交接信息，不调用 LLM、不创建真实工单。

### 领域分与协作

三个业务领域起始分是 General `0.1`、Technical `0`、Billing `0`。意图、关键词和实体提供后续分数。

| 信号 | 加分规则 |
| --- | --- |
| 通用意图 | General `+0.55` |
| 技术意图 | Technical `+0.75` |
| 账单、账户及其具体意图 | Billing `+0.75` |
| 技术或账单关键词 | 每个命中 `+0.18`，各领域上限 `+0.45` |
| 通用关键词 | 每个命中 `+0.12`，上限 `+0.35` |
| 错误码实体 | Technical `+0.20` |
| 金额实体 | Billing `+0.15` |
| 订单号实体 | General `+0.10` |

最高分的可用领域成为主 Agent。其余专业领域分数达到 `0.45` 时进入辅助列表；消息中的明确技术/账单协作信号也可加入辅助领域。General 不作为辅助类型。明确辅助信号不会因为主领域得分很高而被相对比例阈值过滤。

### 监控降权与执行失败

Technical 或 Billing 的全部实例 `monitor_penalty` 达到阈值时，该专业类型退出本次候选集合，也不能经协作信号重新进入辅助列表。阈值默认 `0.5`，读取顺序为 `MYMIND_MONITOR_FALLBACK_PENALTY`、`ECHOMIND_MONITOR_FALLBACK_PENALTY`、默认值。

还有健康实例时保留该专业类型，`_best_agent()` 仅从低于阈值的实例中按 `routing_score()` 选择。没有健康专业候选时由通用或其他健康领域处理；`routing_reason` 追加 `monitor_fallback=[technical]` 等说明。

专业 Agent 执行失败时再调用 GeneralAgent。原先的工具名称与轨迹会合并到回退结果。`primary_agent` 表示原路由主类型；单 Agent 路径的 `agent_type` 表示最终执行类型，回退后可为 `general`。并行路径的 `agent_type` 保留决策主类型，成功执行类型见 `agent_types`。

Composer 默认关闭，成功的主辅回复带角色标签拼接。开启后尝试合成；不足两个成功结果时直接返回已有结果，合成失败时保留主回复和补充说明。

## 4. Agent 工具循环与 RAG

![RAG 工具流程](assets/flows/04-rag-tool-flow.png)

`AGENT_TOOL_USE_ENABLED=true`、`KNOWLEDGE_TOOL_MODE=tool_only` 是默认配置。各业务 Agent 获得角色工具和共享知识工具；知识工具关闭时，API 仍不进行预检索。

1. 统一 LLM 网关发送可用工具 Schema，模型返回普通文本或 `ToolCall`。
2. 无工具调用时结束本次模型循环；有调用时先检查角色白名单和 JSON Schema。
3. `search_knowledge_base` 读取 `query` 与 `top_k`。工具默认 Top-K 为 5，处理时约束为 1–20；同一请求同查询及 Top-K 的已完成结果可直接复用。
4. `MCPToolManager.search_with_rewrite()` 改写查询，保留原查询，再并行执行子查询召回；每路至少召回 5 条。
5. 子查询工具调用经过结果缓存、熔断、参数检查和超时控制。健康结果按稳定片段 ID 去重；降级片段不混入正常知识依据。
6. 对合并片段重排并取 Top-K，结果回送模型。默认知识库为生产向量检索；BM25+RRF 等属于独立 R0–R4 实验配置。

改写失败会保留原查询。片段不超过 Top-K 时 `_rerank()` 直接返回；LLM 重排失败时使用确定性排序。因此 `reranked=true` 不足以证明本次执行了 LLM 重排。管理器最终结果的 `cached` 也不聚合所有子查询命中，应结合工具统计看缓存情况。

默认最多进行 3 个模型轮次。若第 3 轮仍要求工具，工具执行后返回达到上限的话术；不会再自动增加第 4 次回答生成。Provider 明确不支持工具协议时尝试无工具生成并记录降级轨迹。

`AgentCallResult` 的内容、工具名称、轨迹和用量均在调用内管理。续轮模型失败会返回失败结果并保留此前记录，不使用共享 Agent 上的“最近一次”请求状态。

## 5. 知识状态与工具轨迹

| 字段 | 真实含义 |
| --- | --- |
| `knowledge_used` | 已进入检索工具处理；不是知识已被成功采用或回答已验证的保证。 |
| `knowledge_status=used` | 检索工具返回了知识片段。 |
| `empty` | 工具返回无结果，包括管理器的“所有子查询均无结果”。 |
| `degraded` | 工具检索降级。 |
| `error` | 检索工具参数、执行或结果失败。 |
| `skipped` | 无检索工具调用轨迹。 |

同请求的知识状态按 `used → degraded → error → empty` 汇总。有检索轨迹时 `knowledge_reason=agent_tool:<状态>`，否则为 `agent_did_not_search`。参数校验失败仍会记录检索轨迹，但处理函数没有执行，`knowledge_used` 可以为 false。

Trace 默认不采集。开启 `AGENT_TRACE_ENABLED=true` 后保存路由和调用记录；再开启 `TRACE_API_ENABLED=true` 可通过 `/trace/tool/{request_id}` 或 `/trace/tools` 查询。HTTP 服务使用 Redis 跨 Worker 存储，默认保存 24 小时、最近索引最多 200 条。

工具轨迹包含角色、调用 ID、脱敏输入、执行状态、结果状态、耗时、缓存、重排与降级标记，不保存工具完整返回正文。模型续轮失败和 GeneralAgent 回退均不丢掉已经发生的调用。

## 6. 知识导入

`/knowledge/add` 接受标题和正文数组；`/knowledge/upload` 可导入 UTF-8 文本、Markdown 或 JSON 数组。默认生产切块按句子组织，目标大小为 500 字且无 overlap；实际片段长度受原文句子边界影响。

稳定片段 ID 用于 Chroma `upsert`。同一文档重复导入不会增加重复片段，提交正文时 Embedding 随写入生成。响应的 `processed_chunks` 表示本次处理数，`added_chunks` 保留相同的兼容字段；它们不是净新增数量。导入完成后知识结果缓存失效。

同标题但正文或结构变化时，稳定 ID 可以改变，upsert 不会自动删除旧版本片段。当前 API 没有知识删除接口；更新版本需按既有知识库管理方式处理旧内容。

## 7. 记忆与背景预算

![记忆压缩流程](assets/flows/05-memory-compression.png)

Redis 工作记忆与摘要按 `user_id + conv_id` 隔离，每次写入刷新 24 小时 TTL。情景记忆和用户画像分别保存在 Chroma 的 `episodic`、`user_profile` collection。

达到 `COMPRESS_AT=15` 条消息时，Redis 会话锁内压缩旧消息，保留最近 5 条；摘要生成失败时使用占位摘要。新摘要与旧摘要合并，默认最大 1500 字，必要时再次归并。情景记忆保存该次摘要，metadata 中只保留旧消息正文前 500 字，写入失败记录日志后继续完成工作记忆整理。

15 是消息数。空会话第 8 轮写入用户消息时达到第 15 条，先压缩，再写本轮助手消息，工作记忆变成 6 条。`WORKING_MAX=20` 是读取上限，不能当作触发阈值。

ContextBuilder 超预算时依次减少情景记忆、画像字段、较早工作记忆、过长摘要和知识背景，最终限制长度。当前 `/chat` 的知识背景为空，工具结果在后续消息中另行加入；8000 字符预算不是整个模型请求的 Token 上限。

画像更新按用户加锁；没有新用户内容或距离上次成功更新不足 600 秒时跳过模型提炼。生成后以稳定画像 ID 写回 Chroma，后台任务不阻塞正常 HTTP 回复。

## 8. Skills、监控与评测

Skills 在选定角色后的动态 Prompt 构造阶段匹配角色和关键词，默认目录为 `skills/`，由 `mymind_SKILLS_DIR` 覆盖。`/skills/reload` 重新加载文档，单文件解析失败不会阻止其他 Skill。

Monitor 默认每 10 秒采集业务统计。成功率低于 `0.90` 时增加最高 `0.5` 的降权项；平均耗时高于 3000ms 时增加最高 `0.4` 的延迟项，总值不超过 `0.9`。告警触发与路由退出阈值是两个步骤。

`/eval/run` 调用意图识别、编排和四维 Judge。`knowledge_gate_accuracy` 比较实际 `tools_used` 与 `expect_knowledge_search`，多轮期望仅作用于最后一轮。R0–R4 的 KnowledgePolicy 是独立实验基准，运行时不依赖它。

HTTP 生命周期注册完整知识工具、监控与评测；CLI 读取记忆并执行 Agent，但没有初始化知识库工具管理器。接口与运行命令见 [完整使用指南](完整使用指南.md)，源码阅读见 [重点代码](重点代码.md)。

## 9. 验证与能力边界

2026-10-07 程序同步回归为 83 项通过，包含假模型与内存组件下的工具调用、并发隔离、失败轨迹、监控回退、API 状态和 E0–E5 离线门禁；Compose 配置检查通过。

该结果不替代真实模型的回答质量、成本和延迟验收。历史 DeepSeek E0/E5 质量、Judge 完整性和 Token 成本门禁未通过；当前默认开启工具调用与 RAG，不等于开启完整 E5。退款、账户修改和工单创建仍需真实业务系统接入。
