# mymind 完整使用指南

适用范围：本地 Python / FastAPI 主版本，2026-10-07。仓库还包含 Java 后端和 Vue 调试前端；本指南的 API 字段与配置以 Python 为准。

## 1. 目录与运行入口

| 目录 | 作用 |
| --- | --- |
| `api/` | HTTP 服务、组件生命周期与交互式 CLI。 |
| `agents/` | 主辅路由、角色工具、工具循环与 Trace。 |
| `core/` | 意图、Provider 网关、缓存、Skills 和检索基础模块。 |
| `mcp/` | 知识库和查询改写、召回、重排工具链。 |
| `memory/` | Redis/Chroma 三级记忆与背景预算。 |
| `monitor/`、`evaluation/` | 在线统计、路由反馈与端到端评测。 |
| `experiments/`、`data/eval/` | 独立实验入口、语料与标注数据。 |
| `skills/` | 可热加载的业务规范。 |
| `tests/` | 单元与 API 契约测试。 |

HTTP 服务在 `lifespan` 中初始化记忆、知识工具、监控和评测。CLI 只初始化记忆、Skills 与 Orchestrator，未初始化知识库工具管理器；模型若选择知识工具会得到未初始化的失败结果。需要完整 RAG 时使用 HTTP 服务。

已有 `.env` 时保留自己的凭据和连接配置。下面展示配置字段，示例 API Key 需要自行填写，不是可用凭据。

### 模型配置

原生 DeepSeek 端点的配置示例：

```dotenv
LLM_PROVIDER=deepseek
LLM_API_KEY=replace_with_your_key
LLM_MODEL=deepseek-chat
LLM_BASE_URL=https://api.deepseek.com
```

模型名称以自己端点实际支持的名称为准。供应商中立的 `LLM_*` 字段优先；未设置时读取 `ANTHROPIC_API_KEY`、`ANTHROPIC_MODEL` 和 `ANTHROPIC_BASE_URL`。未显式设置 Provider 时，代码依据 Base URL 是否包含 `deepseek` 选择 DeepSeek，否则使用 Anthropic。

| Provider | 代码路径 |
| --- | --- |
| `anthropic` | Anthropic SDK 与 Anthropic 工具结果协议。 |
| `openai` | OpenAI Chat Completions 及函数工具协议。 |
| `deepseek` | 原生端点走 OpenAI 协议；Base URL 以 `/anthropic` 结尾时走 Anthropic 兼容协议。 |

角色模型可分别设置 `MYMIND_GENERAL_MODEL`、`MYMIND_TECHNICAL_MODEL`、`MYMIND_BILLING_MODEL` 和 `MYMIND_COMPOSER_MODEL`，未配置时使用统一模型。

### 宿主机依赖连接

```dotenv
REDIS_PASSWORD=mymind123
REDIS_URL=redis://:mymind123@localhost:6379/0
CHROMA_HOST=localhost
CHROMA_PORT=8001
CHROMA_PERSIST_DIRECTORY=./data/chroma
EVAL_BASELINE_PATH=./data/eval/baseline.json
CONTEXT_MAX_CHARS=8000
mymind_SKILLS_DIR=./skills
mymind_SKILLS_MAX_PROMPT_CHARS=5000
```

默认 Compose Redis 使用密码；`REDIS_URL` 中的密码应与 `REDIS_PASSWORD` 一致。宿主机 Chroma 使用映射端口 `8001`，容器内使用 `chromadb:8000`。Chroma 连接失败时组件可使用配置的本地持久化目录，排查时结合启动日志确认实际存储位置。

### 工具、RAG、监控与 Trace

```dotenv
AGENT_TOOL_USE_ENABLED=true
KNOWLEDGE_TOOL_MODE=tool_only
AGENT_MAX_TOOL_ROUNDS=3
MYMIND_MONITOR_FALLBACK_PENALTY=0.5
MONITOR_INTERVAL=10
AGENT_PROFILE_ENABLED=false
AGENT_ESCALATION_ENABLED=false
AGENT_COMPOSER_ENABLED=false
AGENT_TRACE_ENABLED=false
TRACE_API_ENABLED=false
TRACE_KEY_PREFIX=mymind:trace
TRACE_TTL_SECONDS=86400
TRACE_MAX_ENTRIES=200
```

`tool_only` 注册共享知识工具，`disabled` 移除该工具；API 不会恢复意图预检索。关闭 `AGENT_TOOL_USE_ENABLED` 时所有模型工具均关闭。默认配置启用工具调用与 RAG，其余列出的 Agent 能力默认关闭。

Profile 开启后才采用各角色的温度、Token 参数与角色输入包；关闭时 Agent 首轮 `max_tokens=1024`。Anthropic 协议网关遇到空文本或截断且没有工具调用时可单次扩容重试，实际用量应读取遥测。独立升级节点开启后，CRITICAL/人工请求由 EscalationAgent 整理交接摘要；默认由 GeneralAgent 接待并设置升级标记。Composer 关闭时采用主辅拼接，开启后尝试模型合成。

Trace 需要同时开启采集与查询才能保存并读取。环境变量变化需重启服务；Skill 文件变化可通过热加载生效。

## 5. 对话与多轮请求

首次请求：

```powershell
$chatBody = @{
    message = '应用登录时报401，请帮助排查'
    user_id = 'demo-user'
} | ConvertTo-Json
$chatReply = Invoke-RestMethod -Uri 'http://localhost:8000/chat' -Method Post `
    -ContentType 'application/json; charset=utf-8' `
    -Body ([System.Text.Encoding]::UTF8.GetBytes($chatBody))
$chatReply
```

继续相同会话：

```powershell
$nextBody = @{
    message = '我已经重新登录，问题仍然存在'
    user_id = 'demo-user'
    conv_id = $chatReply.conv_id
} | ConvertTo-Json
Invoke-RestMethod -Uri 'http://localhost:8000/chat' -Method Post `
    -ContentType 'application/json; charset=utf-8' `
    -Body ([System.Text.Encoding]::UTF8.GetBytes($nextBody))
```

`conv_id` 可省略，但每次省略会生成新的会话。`request_id` 属于单次请求，不能代替会话 ID。

| 响应字段 | 解释 |
| --- | --- |
| `response` | 最终助手回复。 |
| `intent/intent_group` | 具体意图与粗领域。 |
| `intent_confidence/intent_source_scores` | 融合置信度与三路原始分数。 |
| `entities` | 订单号、金额、日期、错误码等规则提取结果。 |
| `primary_agent/supporting_agents` | 原路由主辅类型。 |
| `agent_type/agent_types` | 执行类型信息；并行路径的 agent_type 保留决策主类型。 |
| `routing_reason/routing_confidence` | 领域分和路由解释。 |
| `tools_used` | 实际进入处理的工具名称，去重返回。 |
| `knowledge_used/status/reason` | 见下一节。 |
| `escalated` | 意图、CRITICAL 或回复触发的升级标记，不代表真实人工工单创建。 |
| `latency_ms` | Orchestrator 计时，不包括 API 前后的记忆、识别与写入等全部时间。 |

识别为低置信度 `other` 且消息长度大于 2 时，先返回澄清，不调用回复 Agent。复合技术/账单请求可能并行执行；所有实例高降权的专业领域不能进入主辅路由。

## 6. 解释知识状态与 Trace

`knowledge_used=true` 说明已进入检索工具处理，检索为空、降级或失败也可为 true。参数校验失败只记录调用轨迹，处理函数未执行，因此这个字段可以为 false。

| `knowledge_status` | 含义 |
| --- | --- |
| `used` | 返回了知识片段。 |
| `empty` | 没有召回结果。 |
| `degraded` | 工具走了检索降级。 |
| `error` | 工具参数、执行或结果失败。 |
| `skipped` | 没有检索工具调用轨迹。 |

同请求多次检索按 `used → degraded → error → empty` 汇总。`knowledge_reason` 为 `agent_tool:<状态>` 或 `agent_did_not_search`。知识命中不单独证明回答正确，也不证明模型最终充分采用了片段。

开启两个 Trace 开关、重启并发送请求后查询：

```powershell
Invoke-RestMethod -Uri ('http://localhost:8000/trace/tool/' + $chatReply.request_id)
Invoke-RestMethod -Uri 'http://localhost:8000/trace/tools?limit=20'
```

单次返回 `request_id/found/trace`，最近列表返回 `items`。未开启查询时 HTTP 404；过期或不存在时 `found=false`。采集默认 TTL 为 24 小时，最近索引最多 200 条；HTTP 服务以 Redis 支持跨 Worker 查询。

Trace 的 `tool_calls` 保留工具名、调用 ID、脱敏输入、执行和结果状态、耗时、缓存、重排、降级与错误码。模型续轮失败及专业 Agent 回退后，已经执行的工具记录仍然存在。完整工具结果正文不存入这个 Trace。

## 7. 知识导入与显式检索

### 文档批量导入

```powershell
$knowledgeBody = @{
    documents = @(
        @{ title = '退款政策'; content = '购买后七天内可以申请退款，审核通过后原路退回。' }
        @{ title = '登录排查'; content = '401通常表示认证失败。请检查登录状态和Token有效期。' }
    )
} | ConvertTo-Json -Depth 5
Invoke-RestMethod -Uri 'http://localhost:8000/knowledge/add' -Method Post `
    -ContentType 'application/json; charset=utf-8' `
    -Body ([System.Text.Encoding]::UTF8.GetBytes($knowledgeBody))
```

默认生产知识库按句子组织目标 500 字片段，无 overlap，保存在 `knowledge_base`。`upsert` 接受稳定片段 ID 并生成向量；同一文档重复导入不会重复增加。`processed_chunks` 与兼容字段 `added_chunks` 表示本次处理量，`total_chunks` 才是当前总片段数。

文档内容变化可能产生新 ID；upsert 不自动删除旧内容，当前知识 API 不含删除端点。不要把重复导入的幂等性描述成文档替换和旧版本清理。

### 文件上传

在 Python 子目录上传已有 Markdown 示例：

```powershell
curl.exe -X POST 'http://localhost:8000/knowledge/upload' -F 'file=@data/demo_docs/troubleshooting.md'
```

使用 UTF-8 `.txt/.md`，或 JSON 数组 `[{"title":"标题","content":"正文"}]`。文本上传以文件名去扩展名作为标题；JSON 上传直接导入数组。最大文件大小为 10MB，超出返回 413；JSON 格式不符合要求返回 400。

### 查询与统计

```powershell
$searchQuery = [uri]::EscapeDataString('退款到账时间')
Invoke-RestMethod -Uri ('http://localhost:8000/search?query=' + $searchQuery + '&top_k=3') -Method Post
Invoke-RestMethod -Uri 'http://localhost:8000/knowledge/stats'
```

`/search` 的查询与 Top-K 放在 URL Query，默认 `top_k=5`。返回 `query/results/reranked/requested_top_k/returned/index_version/chunk_config`。管理器在改写后并行召回、去重再重排；`reranked=true` 不一定代表实际调用了 LLM 重排。

导入完成后工具结果缓存失效。生产默认仍是向量检索；独立 R0–R4 实验才选择 Markdown 切块、BM25+RRF 和版本化 collection。

## 8. Skills 动态业务规范

查看和热加载：

```powershell
Invoke-RestMethod -Uri 'http://localhost:8000/skills'
Invoke-RestMethod -Uri 'http://localhost:8000/skills/reload' -Method Post
```

推荐文件结构 `skills/<业务名>/SKILL.md`。现有加载器还接受 `.md/.txt/.json`，Markdown 支持简单 front matter；它不是完整 YAML 解释器。示例：

```markdown
---
name: 登录问题排查
description: 技术客服的登录诊断规则
agents: technical
keywords: 登录, 401, 验证码
enabled: true
---

# 登录问题排查

先确认错误码、发生时间与环境，再按认证状态、Token有效期、网络条件检查。
证据不足时只请求必要信息，不声称已经读取后台日志。
```

角色条件满足后，任一关键词命中即可选择 Skill；无关键词则可作为该角色的常用规范。动态 Skill 总预算默认 5000 字符，单块正文也有限长。热加载后检查解析错误和服务命中日志，才能确认实际选中了对应规则。

## 9. 三级记忆与数据库查看

| 存储 | 默认名称 | 内容 |
| --- | --- | --- |
| Redis | `wm:<user>:<conv>` | 最近会话消息，按用户和会话隔离。 |
| Redis | `summary:<user>:<conv>` | 会话累计摘要。 |
| Chroma | `episodic` | 用户情景记忆摘要及会话 metadata。 |
| Chroma | `user_profile` | 用户画像 JSON。 |
| Chroma | `knowledge_base` | 业务知识片段，与记忆 collection 分开。 |

Redis 键的用户和会话部分经过 URL 编码；包含中文或特殊字符时先用 `MemoryManager._wm_key()`、`_summary_key()` 计算实际键。ASCII 演示用户可以直接查看：

```powershell
docker compose exec redis redis-cli -a mymind123 LLEN wm:demo-user:demo-conv
docker compose exec redis redis-cli -a mymind123 LRANGE wm:demo-user:demo-conv 0 4
docker compose exec redis redis-cli -a mymind123 GET summary:demo-user:demo-conv
```

替换为实际用户、会话及密码。Redis List 中最新消息在前；内存读取会恢复时序。

达到 15 条消息后同步压缩旧消息，保留最近 5 条。空会话第 8 轮写用户消息即可能触发；画像写入异步进行，成功更新间隔为 600 秒，没有新用户内容时跳过。情景记忆只在压缩时写入，短会话未产生 episodic 属于正常行为。

用 Python 读取远端 Chroma collection，以下操作只读取已有内容：

```python
import chromadb

client = chromadb.HttpClient(host="localhost", port=8001)
print(client.heartbeat())
print(client.list_collections())
knowledge = client.get_collection("knowledge_base")
print(knowledge.count())
print(knowledge.get(limit=3, include=["documents", "metadatas"]))
episodic = client.get_collection("episodic")
print(episodic.get(where={"user_id": "demo-user"}, limit=3))
profile = client.get_collection("user_profile")
print(profile.get(where={"user_id": "demo-user"}, limit=1))
```

运行服务在本地持久化模式时使用日志中的真实目录，通过 `PersistentClient` 读取相同目录。collection 尚未创建时 `get_collection` 会报不存在，需要先确认对应业务已执行。

## 10. 监控与降权排查

```powershell
Invoke-RestMethod -Uri 'http://localhost:8000/monitor'
```

观察 Agent 成功率、平均耗时、`monitor_penalty` 与 `routing_score`，以及工具的连续失败和熔断状态。默认每 10 秒采样；低于 `0.90` 的成功率或超过 3000ms 的耗时可增加降权。

Technical/Billing 全部实例降权达到默认 `0.5` 时从本次主辅路由移除，`routing_reason` 出现 `monitor_fallback=[...]`。还存在低于阈值的实例则继续使用健康实例。`MYMIND_MONITOR_FALLBACK_PENALTY` 优先于下载版同义配置。

`/monitor` 的背景预算统计是最近一次 API 构造背景的快照，不是请求级历史。需要逐请求诊断时用 `request_id` 查 Trace。缓存遥测位于 Agent 统计中的 `cache_metrics`，Provider 缓存字段缺失应解释为不可用，不能直接认为没有成本。

## 11. 端到端评测与离线实验

评测接口执行所配置的模型和 Judge，会产生实际调用费用。自定义请求示例：

```json
{
  "intent_cases": [
    {"message": "登录一直报401", "expected_intent": "technical_login"}
  ],
  "dialog_cases": [
    {
      "turns": ["我遇到登录问题", "错误码是401"],
      "expected_intent": "technical_login",
      "expected_primary_agent": "technical",
      "expect_knowledge_search": true
    }
  ]
}
```

`question` 用于单轮，`turns` 用于多轮；多轮期望应用于最后一轮。意图匹配按具体意图精确比较，Judge 按相关性、准确性、完整性、有用性评分。`knowledge_gate_accuracy` 比较实际 `search_knowledge_base` 调用与预期，既不等于检索 Recall，也不等于回答有依据。

结果包括 `pass_rate/total/passed/avg_scores/regressions/recommendations/results`。当前指标相对上次报告或 baseline 下降超过 5% 时记录回归。

从仓库根目录运行全量测试；实验命令从 Python 子目录运行：

```powershell
Set-Location D:\Pythonprojects\yan_1\agent\mymind
& 'D:\anaconda3\envs\learn_claude\python.exe' -m pytest -q
Set-Location .\mymind
& 'D:\anaconda3\envs\learn_claude\python.exe' -m experiments.run_experiments --layer agent-migration

```

## 12. 常见问题

| 现象 | 检查位置 |
| --- | --- |
| 启动提示缺少 API Key | `.env` 的 `LLM_API_KEY` 或兼容旧字段；确认进程读取了正确项目配置。 |
| Redis 认证失败 | `REDIS_URL` 密码、Compose `REDIS_PASSWORD` 与当前容器实际密码。 |
| Chroma 连接失败 | 宿主机 8001/容器 8000、启动日志和实际本地持久化目录。 |
| `/health` 为 503 | 生命周期初始化异常；查看应用启动日志。 |
| `/search` 无结果 | 实际 collection、知识片段数、查询和工具熔断统计；不要仅看生成回复。 |
| 聊天 `skipped` | Agent 未选择检索、澄清/升级分支，或工具与知识开关关闭。 |
| 聊天 `empty/degraded/error` | 检查工具轨迹、Chroma、超时、Schema 与返回状态。 |
| Trace 404 或 `found=false` | 两个开关、重启、请求是否产生记录、TTL 和当前 Redis。 |
| 专业意图交给 General | 查看监控回退理由和专业 Agent 是否执行失败。 |
| 用户画像未更新 | 后台任务状态、600 秒间隔、新用户内容、Chroma 与模型日志。 |
| 没有情景记忆 | 会话是否达到 15 条消息并完成压缩。 |
| 修改代码容器仍为旧行为 | 重新构建并更新应用镜像；Skills 热加载只处理 Skill 文件。 |
